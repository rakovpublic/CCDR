## What changed from v49

v49 correctly prevented false promotion, but several blockers were only expressed as gates. v50 adds concrete machine-readable files and optional ingestors for the next run:

- `outputs/dashboard_claim_buckets_v50.json`
- `outputs/p36_highz_radius_quality_reanalysis_v50_<test>.json`
- `outputs/p30_empirical_mask_manifest_v50.json`
- `outputs/p33_alpha_measurement_template_v50.json`
- `outputs/p8_nanograv_par_coordinate_audit_v50.json`

- `outputs/p32_strain_likelihood_template_v50.json`
- `outputs/p40_bb_likelihood_template_v50.json`
- `outputs/p41_q2_wilson_likelihood_template_v50.json`
- `outputs/smd_derivation_predictions_template_v50.json`

## Expected status behavior

- P36 high-z may move from raw gate failure to a large-radius route candidate if raw unit-provenance paths exist, but it will not regain global/publication confirm unless independent-source radius cuts pass.
- P30 will distinguish SDSS route-confirm from global confirm.
- P33/P32/P40/P41/SMD will remain non-confirming until the corresponding likelihood/measurement JSON or CSV is supplied or generated by the tests.
- Dashboard no longer counts coverage, readiness, or not-confirmed statuses as claim-grade confirms.

## Safety policy

The patch intentionally prefers fewer confirms over false confirms. It creates the exact JSON schema needed to turn blocked tests into confirms in later runs.
